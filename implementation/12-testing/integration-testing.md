# Purpose
Defines the integration testing approach using real databases and transaction rollbacks.

# Scope
Testing commands end-to-end, event emissions, DB constraints, and cross-module interactions.

# Authority
- Authority: EXISTING INFRASTRUCTURE (Vitest 4.1.10)
- Authority: Bible V1 (PostgreSQL, Prisma)

# Prerequisites
- Dedicated test database running locally and in CI.

# Specification Requirements
- WHAT MUST EXIST: Tests that verify commands successfully persist data, enforce tenancy, and emit domain events (MET-EVE-001→002).

# Approved Architecture
- **Database:** PostgreSQL via Prisma.
- **Isolation:** Transaction rollback per test.

# Implementation Contract
- Setup test tenants before each test suite.
- Execute commands through the full command pipeline (authorization, validation, execution, audit).
- Verify Prisma writes the expected data.
- Verify event bus receives the expected domain events.

# Constraints & Invariants
- INV-001: Strict Tenancy Isolation (Cross-tenant DB writes must fail).
- INV-002: Read-Only Closed States (Updates to closed states must fail at the DB/Prisma layer).

# Dependencies
- Depends on local PostgreSQL instance.

# Failure Modes
- Database state corruption between tests: Enforce strict `beforeEach` transaction initiation and `afterEach` rollback.

# Testing Requirements
- Validate MET-ACT-004 (Event emission) by asserting on the event outbox or mocked event bus.

# Conformance Checks
- Audit logs generated by commands must be verified in these tests (EXE-AUD-001).

# Traceability
- MET-ACT-001→004, MET-EVE-001→002, EXE-AUD-001→003

# Open Decisions
- IMPLEMENTATION DECISION REQUIRED: Transaction rollback mechanism (e.g., Prisma interactive transactions vs pg specific savepoints).
