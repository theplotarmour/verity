# Do Not Do

Do not:

- call Verity a Factory Operating System in canonical docs,
- treat VEDA as the target domain model,
- add client-specific conditions in shared code,
- use pack key as authorization,
- use frontend hiding as security,
- create nav outside module manifests,
- create dashboard widgets outside module/dashboard manifests,
- add optional module actions without guards,
- accept tenant ids from clients as security boundaries,
- seed every tenant with manufacturing or restaurant data,
- delete module data on disable,
- claim "module platform complete" until blank tenant and disable scenarios pass.
