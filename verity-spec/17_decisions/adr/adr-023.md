# Architectural Decision Record

## ADR-023: Structured Minimalism Replaces Glass as the Default Material System

*   **Decision ID**: ADR-023
*   **Question**: Does the Verity Experience System continue to use a controlled glass material (ADR-011) as its default surface treatment, or does it move to a fully solid, flat material system?
*   **Context**: ADR-011 settled a prior conflict by adopting glass — translucency, blur, hairline border, ambient shadow — as a first-class, level-assigned material across five surface levels (0–5), reserving solid treatment for dense tables, forms, and semantic/destructive surfaces only (level 5). That decision was made against product-owner reference boards showing atmospheric, translucent depth.

    The product owner has since supplied new, more complete reference screens: a full Settings/Appearance flow and a full Home dashboard, each rendered in both a light theme (warm neutral cream/tan background, solid white/cream cards, thin hairline borders, soft directional shadow, no blur anywhere) and a dark theme (navy-black background `~#0A0E1A`, solid slightly-lighter navy cards, same hairline-border-plus-shadow treatment, no blur). Every persistent surface in both themes — settings cards, stat tiles, the chart card, the live-preview panel, the AI-assistant panel — is opaque. None uses `backdrop-filter`.

    The product owner's direction, given directly against these references: forget glassmorphism, adopt this solid language completely, because it reads as "professional" rather than the glass system's current effect, judged "childish." This is an explicit, evidenced product-owner call against a complete reference implementation — not an inference about ambiguous text, which is the situation ADR-011 resolved. It is the same class of instrument ADR-011 itself was (an explicit decision outranking a prior reading), pointed the other direction.
*   **Affected Concepts**: Experience System material hierarchy; Experience Shell chrome; card, table, control and overlay surfaces; the four glass surface classes (`.glass-shell`, `.glass-card`, `.glass-control`, `.glass-overlay`) and `.verity-solid`; light/dark theming; accessibility contrast; rendering performance. **Not affected**: accent-token derivation (`--accent-seed`, `color-mix`, computed contrast), the monochrome mark rule, semantic-color independence from accent — all ADR-012 mechanics carry forward unchanged, applied to solid surfaces instead of glass ones.
*   **Evidence**: The reference screens (Settings/Appearance, light and dark; Home dashboard, light and dark) are attached product-owner evidence, the same evidentiary class ADR-011 relied on. Every persistent surface across all four renders is fully opaque with a 1px hairline border and a soft, non-tinted shadow; none shows translucency, blur, or a layered gradient tint. The dark render in particular demonstrates that the desired depth and hierarchy — card separation from the page background, elevation of the live-preview and AI-assistant panels — is achieved through solid-surface contrast and shadow alone, not through glass.
*   **Evidence Location**: Product-owner reference screenshots (4 images: Settings/Appearance light ×2 duplicate, Settings/Appearance dark, Home dashboard dark), this session, 2026-09-17; `taskplans/111_global_settings_and_shell_ux_pattern.md` (the taskplan this ADR resolves — see its "Open question" section, which flagged exactly this fork and declined to resolve it without an explicit product-owner call).
*   **Options**:
    *   *Option A*: Keep ADR-011's glass hierarchy as the default; treat the new reference screens as one client-specific skin, not evidence for a platform-wide change.
    *   *Option B*: Replace glass with a **solid, flat material system** as the new default across all five of ADR-011's former levels — depth and hierarchy now come from background/card tonal contrast, hairline borders, and directional shadow, not translucency.
    *   *Option C*: Keep glass available as an optional accent-adjacent material (opt-in per tenant or per surface) alongside a new solid default.
*   **Recommendation**: Option B.
*   **Status**: `ACCEPTED`
*   **Owner**: Product Owner
*   **Resolution**: Adopt Option B.

    Glass is **no longer the default Verity Experience System material.** The reference screens' solid, flat, structured-minimalist treatment is the new default, replacing ADR-011's five-level glass hierarchy for both light and dark themes and for every tenant.

    **The canonical principle.** Verity combines Apple-grade restraint and information clarity with a **solid, structured surface system**: opaque cards, thin hairline borders, generous whitespace, soft non-tinted shadow for elevation, and configurable accent carried through icon chips, active states, and controls. The interface should feel calm, precise, and professional — depth and hierarchy come from spacing, tonal contrast, and shadow, not from translucency.

    **Material system.** One material, not five levels:

    | Surface | Treatment |
    |---|---|
    | Page background | Flat tonal field — warm neutral in light (`#F7F8FA`-family), near-black navy in dark (`~#0F1115`-family); no gradient mesh, no atmospheric blur |
    | Shell / navigation | Solid, same tonal family as the background, separated by a hairline border only |
    | Cards / panels (all levels, all content) | Fully opaque, `1px` hairline border, soft ambient shadow (never tinted to the accent), consistent corner radius — the same treatment previously reserved for ADR-011's level 5 now applies everywhere |
    | Interactive controls | Solid fill or outline, accent-tinted only on selected/active/hover state, never glassy |
    | Elevated/floating surfaces (menus, popovers, modals) | Solid with a stronger shadow for separation, never blur-backed |

    **What is removed.** `backdrop-filter` / blur as a surface treatment is removed from the default system. The four glass classes (`.glass-shell`, `.glass-card`, `.glass-control`, `.glass-overlay`) are deprecated for new work; `.verity-solid` becomes the single card/panel material going forward. ADR-011's six binding constraints (contrast, performance, hierarchy, parity, reduced-transparency, subordination) are moot for the removed material but their *intent* — composited-contrast AA, light/dark parity, content over effect — carries forward unchanged as constraints on the solid system instead.

    **What is unchanged (ADR-012 stands).** Accent remains configurable, ten presets plus custom, derived through `--accent-seed` and computed contrast, never hard-coded per component. The mark stays monochrome everywhere. Semantic colors stay independent of accent. None of this required glass; all of it applies identically to solid surfaces.

    **What this does not license.** This is not permission to reduce information hierarchy, remove whitespace structure, or drift toward generic flat enterprise SaaS with no point of view — the hairline-border-plus-shadow system in the reference screens is itself a considered material choice (soft, warm, generous radius, quiet iconography), not an absence of one. `taskplans/111_global_settings_and_shell_ux_pattern.md`'s in-scope structural patterns (Settings shell, Home dashboard IA) remain the concrete target; this ADR settles only the surface-material question that taskplan explicitly left open.

    Option A was rejected because the product owner's direction was explicit and evidenced across a complete reference set (light and dark, two full page types), not a single ambiguous board — the same standard ADR-011 itself used to override a prior default. Option C was rejected because a tenant-toggleable material would fragment the design system exactly the way brand/accent separation was designed to avoid, and no product requirement calls for it.
*   **Supersedes**: ADR-011 in full — its five-level glass material hierarchy, the four glass surface classes as the default treatment, and its six glass-specific binding constraints. ADR-011's accent/mark/semantic-color content does not exist in ADR-011 (that content lives in ADR-012) and is unaffected here.
*   **Superseded By**: none (current)
*   **Confidence**: `HIGH`
