# Architectural Decision Record

## ADR-024: Scoped Glass Returns for Structural Chrome; Default Accent Reverts to Gold, Tint-Only

*   **Decision ID**: ADR-024
*   **Question**: Does the Verity Experience System keep ADR-023's fully solid material as the default everywhere, or does it reintroduce translucent material on structural chrome specifically — and does the default accent stay Verity Mint or revert to Gold?
*   **Context**: ADR-023 (2026-09-17) replaced ADR-011's five-level glass hierarchy with one solid material everywhere, on explicit product-owner direction against reference screens. That direction stands for what it was evidenced against: dense settings/dashboard content screens. It was never evidenced against, and did not consider, the platform's *structural chrome* — sidebar, top bar, command palette, dropdowns, modals — the surfaces every operating-system-grade interface (and Apple's own HIG, specifically WWDC 2018 "Designing Fluid Interfaces" and the associated materials guidance) treats as a distinct, translucent layer precisely because they are not content: they float over content and should read as doing so.

    The product owner has now given fresh, explicit direction: rebuild Verity's craft language against Apple's own design discipline — motion, materials, typography — while keeping the density and restraint of Vercel/Linear/Raycast/Resend for actual data surfaces, and correcting a concrete defect surfaced in this same conversation: the current default accent (Verity Mint, ADR-012) is applied in dark mode as a large flat filled background (e.g. the Outreach "Current Direction" banner), which reads as heavy and undifferentiated rather than as an accent.

    Critically, this is not a request to rebuild a material system from scratch. `src/app/globals.css` still contains ADR-011's complete glass ladder (`--color-glass-1` through `--color-glass-4`), the four glass utility classes (`.glass-shell`, `.glass-card`, `.glass-control`, `.glass-overlay`), their blur variables, and a working `prefers-reduced-transparency` fallback that flattens every glass class to solid. ADR-023 stopped *using* this system by default; it never deleted it. This decision reactivates it, scoped narrowly, rather than reintroducing ADR-011's five-level hierarchy wholesale.
*   **Affected Concepts**: Experience System material hierarchy (chrome only — `ShellChrome`, `CommandPalette`, `AgentChatDock`, `Modal`, `OverflowMenu`, `Combobox` dropdowns, `ProfileMenu`); default accent seed and its derived tokens (`--accent-seed`, `DEFAULT_ACCENT`); a new constraint on accent *usage* (tint/interactive-only, never a large fill) that ADR-012 did not state. **Not affected**: ADR-023's solid-material call for dense content (`DataTable`, forms, prospect cards, `Panel`/`Surface` in `primitives.tsx` used for record content, `PermissionDenied`) — that call was correct for the surfaces it was evidenced against and remains in force for them. The monochrome mark rule, semantic-color independence from accent, and the ten-preset accent system (ADR-012 mechanics) all carry forward unchanged.
*   **Evidence**: This conversation, 2026-09-18 — explicit product-owner direction ("leave the current and past design completely make verity as if its made by apple dev complete ui ux") following review of (a) a NEW brand-identity board, gold-primary (`#D4A017`), supplied by the product owner this session at `C:\Users\divyo\OneDrive\Desktop\PlotArmour\Verity\f0ec2b60-f00e-4dcf-afae-738bebfeb525.png` — **not yet committed to the repository**; the repo's existing `design/verity asthetics.png` is still the prior, mint-primary (`#00D1B2`) board ADR-012 was written against, and (b) a live screenshot of the current Outreach dashboard showing the accent-as-large-fill defect on the "Current Direction" banner. Gold itself is not new to the system — it was already `ACCENT_PRESETS`'s second entry ("Warm Sand Gold `#D4A017`") before this decision — but the NEW board is the first evidence establishing gold as the *intended default*, superseding the repo's existing mint-primary board for that specific question.
*   **Evidence Location**: This session's conversation transcript, 2026-09-18; `src/app/globals.css` (glass ladder and utility classes, lines ~40–120 and ~480–710, confirmed present and unused by default since ADR-023); the new gold-primary board at the Desktop path above (not yet copied into `design/`); the repo's existing `design/verity asthetics.png` (mint-primary, ADR-012's original palette authority, now superseded on the default-accent question only); `~/.claude/skills/apple-design/SKILL.md` (WWDC "Designing Fluid Interfaces" / "Principles of Great Design," loaded this session as the craft-discipline reference).
*   **Follow-up required, not yet done**: the new gold-primary board should be copied into `design/` (e.g. `design/verity-aesthetics-v2.png`) and cited by path from the repo, not left as an external Desktop reference — an ADR whose primary evidence lives outside the repository is not reproducible by the next person who reads it. Flagged here rather than done silently, since moving/renaming a design asset is a small but real action worth a beat of confirmation.
*   **Options**:
    *   *Option A*: Keep ADR-023's solid-everywhere default unchanged; treat the new direction as a request for polish (contrast, spacing) within the existing solid system rather than a material change.
    *   *Option B*: Reactivate the existing, still-present glass classes on structural chrome only (sidebar, top bar, command palette, modals, dropdowns/menus), keep `.verity-solid` on all dense-content surfaces exactly as ADR-023 specified, and revert the default accent to Gold with a new tint-only usage constraint.
    *   *Option C*: Reintroduce ADR-011's full five-level glass hierarchy everywhere, superseding ADR-023 in full.
*   **Recommendation**: Option B.
*   **Status**: `ACCEPTED`
*   **Owner**: Product Owner
*   **Resolution**: Adopt Option B.

    **Material system — two treatments, not five levels, not zero.**

    | Surface class | Treatment |
    |---|---|
    | Structural chrome — sidebar, top bar, `ProfileMenu` dropdown, `CommandPalette`, `AgentChatDock`, `Modal`, `OverflowMenu`/`Combobox` popovers, mobile nav sheet | `.glass-shell` / `.glass-control` / `.glass-overlay` (existing classes, reactivated) — translucent, blurred, content scrolls or sits beneath |
    | Dense content — `DataTable`, forms, prospect/record cards, `Panel`/`Surface` for record content, `PermissionDenied` | `.verity-solid` (ADR-023, unchanged) — opaque, hairline border, soft shadow |

    This mirrors the apple-design skill's own §12 rule almost exactly ("build nav/toolbars/sheets as translucent layers... dense tables, long-form text stay solid") — it is also, not coincidentally, close to ADR-011's original constraint list before ADR-023 retired the system wholesale. This decision is best read as *reinstating a narrower, more disciplined version of ADR-011*, not inventing a fourth system.

    **Accent — reverts to Gold, gains a usage constraint ADR-012 lacked.** Default `--accent-seed` / `DEFAULT_ACCENT` changes from Verity Mint `#00D1B2` to Warm Sand Gold `#D4A017` — already an existing preset (`ACCENT_PRESETS` in `src/server/platform/accent.ts`), not a new color. New constraint: **accent governs small and interactive surfaces only** — buttons, links, focus rings, active nav state, badges rendered as a tint/outline — and is **never used as a large filled background**. The Outreach "Current Direction" banner's current flat-fill treatment is the concrete defect this constraint is written against; it must be rebuilt as a bordered card with a small accent accent (icon, label, or edge treatment) rather than a full-surface tint.

    **Motion.** New craft layer, not previously governed by any ADR: interactive/transient surfaces (modals, dropdowns, command palette, button press states) adopt spring-based motion per the apple-design skill's parameters — critically damped (`damping 1.0`, `response ~0.35`) by default, slight bounce (`damping ~0.8`) reserved for genuinely gesture-driven interactions. `framer-motion` is already an installed dependency. `prefers-reduced-motion` must cross-fade instead, matching the existing `prefers-reduced-transparency` fallback's spirit.

    **Typography.** No font change — Inter remains locked (ADR-012, brand board). Discipline changes: size-specific letter-spacing (negative tracking on large Light-300 headings, near-zero on body), leading that tightens on headings and stays generous on body, per the apple-design skill §15 and the brand board's own existing Light-heading / 1.7-body-leading rule.

    Option A was rejected because it treats a craft-and-material direction as a polish request, which understates what was asked and would leave the accent-as-fill defect and the flatness of structural chrome unaddressed. Option C was rejected because ADR-023's evidence for solid-on-dense-content was real, evidenced, and unrebutted by anything in this decision's own evidence — reintroducing glass on tables and forms would repeat the exact defect ADR-023 correctly fixed (translucency behind data that needs to stay legible and calm).
*   **Supersedes**: ADR-023, in part — narrows its "solid material everywhere" default to "solid material on dense content," restoring glass on structural chrome only. ADR-023's solid-content call, all six of ADR-011's carried-forward intent constraints (contrast, parity, reduced-transparency, subordination) as applied to dense content, and its removal of glass *as the content default* all remain in force. ADR-012's default-accent clause, in part — Gold replaces Mint as `DEFAULT_ACCENT`; every other ADR-012 mechanic (ten-preset system, monochrome mark, semantic independence, `color-mix` derivation) is unaffected and carries forward unchanged, now with the added tint-only usage constraint.
*   **Superseded By**: none (current)
*   **Confidence**: `MEDIUM` — the material and accent decisions are grounded in explicit product-owner direction and existing, previously-evidenced infrastructure (high confidence on mechanism); the specific chrome/content surface split and motion parameters are this session's own synthesis of that direction against the apple-design skill, not separately evidenced against product-owner-supplied reference screens the way ADR-011/023 were — expect refinement once a proof surface is built and reviewed.
