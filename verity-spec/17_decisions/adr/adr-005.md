# Architectural Decision Record

## ADR-005: Tenant vs Organization Boundaries

*   **Decision ID**: ADR-005
*   **Question**: How do we define the boundary between Tenant and Organization?
*   **Context**: Spec mismatch between Organization representing the tenant boundary vs a nested hierarchy under Tenant.
*   **Affected Concepts**: `Tenant`, `Organization`, `Location`
*   **Evidence**: Keycloak Realms (tenancy) vs Groups/Organizations (organizational units).
*   **Evidence Location**: Keycloak Realms; Odoo res.company nested structure.
*   **Options**:
    *   *Option A*: Tenant and Organization are the same boundary.
    *   *Option B*: Tenant is the root data isolation boundary; Organization is a nested business unit hierarchy under Tenant.
*   **Recommendation**: Option B.
*   **Status**: `ACCEPTED`
*   **Owner**: Product Owner
*   **Resolution**: Adopt Option B. The product-level invariant is **tenant isolation** (preventing any cross-tenant data leaks). Tenant represents the root security partition. Organization is a logical operational branch/division within a Tenant. Note that database-level Row-Level Security (RLS) is one implementation mechanism to enforce tenant isolation, not the product invariant itself.
*   **Supersedes**: None
*   **Superseded By**: None
*   **Confidence**: `HIGH`
